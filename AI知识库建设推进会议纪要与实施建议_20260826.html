01执行摘要：三层架构、一个业务目标

01

通用常规知识库

产品、标书、合同、流程和质量知识按版本管理；由受控检索智能体限定来源、强制引用和证据不足拒答，并评估 WeKnora 等专业知识库/RAG 平台。

02

ERP 动态数据服务

订单状态、库存、交期、履约和应收等动态信息以 ERP 为事实源，Agent 通过中间件白名单接口实时查询。

03

ERP 受控写入服务

Agent 只生成结构化草稿；经人工确认、权限与字段校验后，通过 ERP 厂商正式 API 写入，并保留完整回执与审计。

核心目标：第一阶段不以“上传多少文档”为成果，而以客服部是否更快完成标书、合同评审和销售查询支撑，以及销售内部信息搬运时间是否下降为成果。

04不依赖 ERP 的通用常规类知识库

首批知识范围

  • 产品共享：规格、选型、资质、应用范围。
  • 标书：模板、章节、附件清单、历史优秀案例。
  • 合同：标准模板、条款库、风险条款、评审规则。
  • 客服：流程、SLA、表单、异常升级、FAQ。
  • 质量：医用注塑规范、检验标准、投诉和偏差 SOP。

每份知识的必备元数据

  • 知识 ID、标题、知识类型。
  • 业务负责人、来源部门、原始文件。
  • 版本、状态、生效和复审日期。
  • 适用产品/客户/业务阶段。
  • 保密级别、关键词、关联流程。

受控检索智能体：限定所有答案来源

01

员工提问

提出产品、合同、标书、流程或质量问题。

02

意图与权限

识别知识域，按人员、部门和保密级别过滤。

03

专业知识库

在 WeKnora 等经选型验证的平台中检索证据。

04

证据检查

检查相关性、有效版本、冲突和引用覆盖。

05

约束生成

只依据召回证据回答，禁止凭模型记忆补全。

06

引用或拒答

返回文件、版本、生效日期；证据不足则升级。

智能体的硬约束

  • 限定来源：只允许已批准且用户有权访问的知识库，默认禁止互联网、模型记忆和未审核个人笔记。
  • 先检索后回答：无证据、版本冲突或相关性不足时必须拒答。
  • 强制引用：关键结论附知识 ID、文件、版本、生效日期和原文位置。
  • 权限前置：检索前过滤部门、产品、客户与保密级别。
  • 全链路留痕：记录问题、命中文档、模型、答案和人工修改。

Workbuddy 与专业平台的边界

  • Workbuddy 适合个人效率、通用检索、任务编排和快速试验。
  • 若缺少知识域白名单、版本过滤、引用校验和拒答机制，可能出现来源偏差或幻觉。
  • 正式部门/公司知识服务应评估 WeKnora 等专业知识库/RAG 平台。
  • 选型必须验证解析、混合检索、重排、元数据、权限、审计、更新与 API，而不是只看产品名称。

专业知识生成：模型能力 × 专业 Skill × 审核

适用边界：Workbuddy 或豆包可用于会议纪要、通用摘要、格式转换、初步 FAQ 和普通文案；合同条款分析、医用注塑规范提炼、质量处置方案和复杂标书等专业生成，需要更强推理模型、专业 Skill、权威知识库、固定模板、测试校验和业务专家审核。

更强推理模型

负责复杂对比、冲突识别、风险判断和多步推理；模型能力决定专业生成的上限。

专业 Skill

固化任务边界、输入、来源政策、推理步骤、输出结构、校验规则、拒答和审批人。

知识发布闭环

生成结果一律为 AI 草稿；专家审核、赋予元数据并发布后，才可成为权威知识。

工具与模型分级

任务类型工具/模型策略发布规则
通用整理Workbuddy、豆包或成本较低模型人工快速抽检，可作为工作草稿。
专业检索问答专业知识库平台 + 受控检索智能体 + 合适模型强制引用；证据不足必须拒答。

05通过 ERP 获取数据：查询与写入分离

类型示例正确处理方式
稳定知识合同规则、标书模板、产品规范进入知识库，按版本检索并引用。
实时业务数据订单、库存、生产进度、交期、应收通过 ERP 中间件实时查询，ERP 为事实源。
组合答案“订单何时交付，延期后如何处理？”ERP 查询交期 + 知识库检索延期 SOP，Agent 合并并标明来源。

ERP 只读查询架构

01

员工提问

提供合同号、订单号、客户或物料等条件。

02

Agent 编排

识别意图、补齐参数，决定是否需要实时查询。

03

身份与权限

岗位授权、字段脱敏、越权拦截。

04

ERP 中间件

调用白名单查询服务，不允许自由 SQL。

05

ERP / BI

返回结构化、可追溯的实时业务结果。

06

组合回答

结合 SOP 解释，显示来源与查询时间。

第一批只读查询

履约进度

按合同号/订单号查询当前环节、责任部门和状态。

交付与阻塞

查询预计交付时间、当前阻塞点及可联系责任人。

发货/质检/财务

按权限查询物流、质检、投诉、开票或应收状态。

06分阶段实施路线

P0｜0–2 周

治理、平台与静态试点

标书/合同/质量用例；验证受控检索智能体及 WeKnora 等专业平台候选；测试引用和拒答。

P1｜2–4 周

ERP 只读查询

通过中间件开放订单、履约、交付等 3–5 个白名单接口。

P2｜4–8 周

组合问答与异常协同

实时状态与 SOP 组合回答；提供异常原因和责任人指引。

P3｜治理稳定后

受控数据写入

Agent 生成录入草稿，人工确认，通过 ERP 厂商 API 写入。

P4｜价值验证后

公司级知识网络

部门库联网、统一身份权限、跨库检索和公司级目录。

一期只建议批准三个用例

01

标书资料准备助手

推荐产品资料、资质附件和标书章节，列出缺失项；不依赖 ERP。

02

合同评审助手

对照标准条款和评审规则生成风险清单，不替代审批人判断。

03

订单履约查询助手

通过中间件实时查询当前环节、预计交付和阻塞点，显示来源与时间。

07其他方面的建议

明确知识治理角色

业务 Sponsor 管范围和价值，客服/质量负责人管知识正确性，IT 管权限接口，实施负责人管方法、测试和节奏。

成本不能只看 Token 单价

低价模型用于分类、去重和摘要；合同、质量、写入前校验按风险、准确性和人工复核成本选择模型。

教程升级为岗位任务指南

除截图和点击步骤外，必须有输入示例、预期结果、失败处理、保密提醒、自测题和 30–45 分钟现场演练。

验证“销售 60% 内部沟通”

用一周样本记录次数、等待时间、涉及部门和未解决原因；上线后用同口径对比，形成可信 ROI。

单机试点必须有退出路径

明确最终迁移平台、权限、备份和人员变更接管机制；权威知识不能长期只留在个人电脑。

先建立测试集再发布

每个用例至少 20 个真实问题，覆盖正常、歧义、无答案、过期资料和越权请求。
