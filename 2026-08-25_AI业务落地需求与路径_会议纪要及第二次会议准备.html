AI 业务落地需求与路径

第一次会议纪要 · 两部门会后作业 · 第二次 AI FDE 会议准备

会议时间：2026-08-25 13:36:06实施部门：生产计划部、客服部实施负责人：张强

01执行结论：先把业务画清楚，再让 AI 进入流程

01

自动排产不是第一步

先明确订单、库存、BOM、工艺、产能、交期、例外和责任人；数据与规则不可信时，AI 只会更快地产生错误。

02

两个快速验证点

首批建议做客服订单/发票/交付只读查询，以及管理层生产经营日报，均可在 2–4 周内用真实样本验收。

03

包装知识单独治理

将管芯、卷长、标签、托盘、客户特殊要求从个人电脑和经验中提取，形成客户—产品—包装版本的权威标准。

04

中间件不是万能药

必须明确字段来源、同步频率、口径、权限、失败处理和审计；写入仍需 ERP 正式 API 与人工审批。

05

流程图要用对工具

泳道图描述端到端流程，数据流图描述数据来源，鱼骨图分析根因，决策表固化判断规则。

06

业务负责验收

AI 是答卷人，业务部门负责出题、提供标准答案和评分；没有负责人、样本与指标的场景不进入 PoC。

记录边界：本文依据会议材料整理。“90% 为备货订单”、ERP/WMS/BI 数据差异及中间件能力均为会议陈述，第二次会议前须用系统数据、字段字典和真实样本核实。

02第一次会议整理

板块会议反映的现状/痛点初步 AI 方向关键前提
客服与履约订单、发票、追单需人工查 ERP；合同标书录入繁琐；包装要求散落在个人电脑和经验中。订单/发票/交付查询、录入草稿、包装知识库、企微问答。权限、状态口径、客户/产品主数据、包装标准。
生产计划排产依赖计划员；库存、到料、产能、工艺、BOM、交期约束复杂；反复口头确认。齐套检查、约束核对、排产建议、异常解释。库存/工单/BOM 可信；产能日历、工艺规则、交期或预测可用。
管理层汇报Excel 手工统计滞后；部门数据不一致；BI 与工序核算存在偏差，管理层不信任。中间件取数、口径校验、异常分析、日报/PPT 自动生成。指标定义、数据血缘、刷新时点、正确日报样本。
会议共识：AI 是业务执行的“答卷人”。基础流程不清、数据不准、规则不明时，不进入复杂自动化；先做可读、可控、可回退的单点试点。

03统一八类原子动作口径

AC1

获取 / 搜集

查订单、库存、规范和历史资料；使用知识库、搜索和系统只读查询。

AC2

录入 / 搬运

从合同、邮件、Excel 搬到 ERP/BOM/工单；使用 OCR、RPA 和受控 API。

AC3

转换 / 整理

拼表、汇总、去重、格式转换和分类；使用 Agent、代码和清洗规则。

AC4

比对 / 核对

核库存、BOM、工艺、包装和账目；使用规则引擎与 AI 校验。

AC5

判断 / 决策

识别异常、分析取舍和风险预警；AI 只提供建议，责任人决策。

AC6

生成 / 撰写

生成日报、PPT、回复和工单草稿；重要内容由业务专家审核。

AC7

沟通 / 协调

纪要、催办、提醒和跨部门状态同步；不能替代组织责任。

AC8

操作 / 执行（物理）

开设备、加工、搬运和装配；依赖人员、机器人、视觉与自动化设备。

口径修正：会议口述的“知识库咨询”是业务场景，通常由 AC1 获取证据、AC5 理解判断、AC6 生成回答组成，不再作为独立原子动作。

04FDE 专家复盘：真正的四个根因

流程未显性化

排产和包装依赖口头确认与个人经验。应画现状泳道图，标出例外、等待与回退。

数据口径不一致

ERP、线下台账、BI 结果不一致，工单关闭不及时。应建数据问题台账与责任人。

销售预测缺失

框架/备货订单出货时间变化，后端无法稳定备料排产。需同步推进预测和变更管理。

知识未结构化

包装与工艺限制分散，导致新人学习慢和版本错用。需建权威知识与规则表。

四种图各自解决什么问题

A

泳道流程图

谁在什么时候做什么、与谁交接、在哪个系统完成。

B

数据流图

数据在哪里产生、存储、更新、同步和被谁使用。

C

鱼骨图

分析库存不准、计划频繁调整、包装错误等问题的根因。

D

规则 / 决策表

把优先级、阈值、约束、例外和升级条件变成可执行规则。

包装痛点必须拆成独立子流程

包装流程：需求获取 → 标准匹配 → 客户/内部确认 → 生产与包装执行 → 检验与留证 → 版本更新。包装不能只作为订单备注存在。
类别建议采集字段
客户与适用范围客户、收货地、产品、规格、订单类型、适用日期。
卷材/内包装管芯材质与尺寸、卷长、卷径、卷向、接头、内袋、干燥剂、洁净要求。
标识与标签标签模板、语言、条码/二维码、批号、客户料号、标签位置。
外包装箱型、装箱数量、隔板/护角、封箱、箱唛、重量限制。
托盘与运输托盘材质/尺寸、码放、缠绕、打带、防潮、防震、运输方向。
质量与合规外观、洁净、异物、法规/客户标准、检验、留样或照片要求。
版本与审批标准编号、版本、生效日期、客户确认件、审批人、变更原因。

包装痛点要量化

  • 每周询问、等待、返工和投诉次数。
  • 新人找到正确标准所需时间。
  • 同一客户/产品存在的版本数。
  • 个人电脑、聊天记录、纸张和脑中知识占比。
  • 临时变更影响部门与漏通知情况。

客服必须提供

  • 最近 4 周查询记录和 20 个完整履约案例。
  • 10–20 份合同/订单/标书及正确录入结果。
  • 包装标准、确认件、标签模板、历史备注和异常。
  • 查询入口、字段、权限与跨部门等待时间。

包装知识结构

客户 └── 收货工厂 / 地址 └── 产品 / 规格 ├── 默认包装标准 ├── 客户特殊要求 ├── 标签与箱唛模板 ├── 适用订单 / 日期 ├── 当前有效版本与历史版本 ├── 客户确认件与内部审批 └── 异常、投诉与纠正措施

07数据与技术路线：查询、分析、写入分开

01

业务入口

企微机器人、业务页面或固定日报任务。

02

AI Agent

识别意图、补齐参数、检查权限与风险。

03

受控工具层

中间件只读查询、权威知识库、ERP 正式 API。

04

业务结果

带来源、口径、查询时间的回答、报告或草稿。

05

控制与审计

人工确认、写入回执、日志、拒答与异常回退。

中间件专项第二次会议必须确认
数据血缘与口径字段来自哪个业务对象，是否清洗；可用库存、未结工单、预计交期、损耗率如何定义。
时效与质量实时/分钟/小时/T+1；空值、重复、异常和跨系统差异如何处理。
权限与可用性岗位字段权限；接口超时、同步失败和数据缺失的提示与回退。
写入与审计允许写入的对象、审批、防重复、回执；查询和写入的完整留痕。
安全红线：AI 不直连生产数据库执行自由 SQL；查询与写入账号分离；工单、BOM、订单先生成草稿；排产建议不自动下达；质量数据不自动放行；客户、包装、工艺和价格按最小权限访问。

08场景优先级与实施路线

P0-1

客服履约查询

3–5 个高频意图，中间件只读查询。衡量响应时间、准确率、跨部门询问、人工转接与使用率。

P0-2

生产经营日报

固定数据快照生成日报、异常和待办。衡量准备时间、数字争议、发现时效和修改率。

P0-3

包装知识助手

先覆盖一个客户/产品范围，完成 30 个问题测试，强制显示标准、版本和引用。

P1

订单录入草稿

对 20 份合同/订单抽取字段并核对，先输出草稿，不直接写入生产系统。

P1

齐套与约束检查

用历史订单离线检查缺料和工艺冲突，验证数据与规则是否可用。

P2

排产建议

历史数据离线回放，与计划员结果比较；达标后才决定是否接入真实流程。

阶段一｜1–2 周

流程与数据体检

完成流程图、数据流、鱼骨图、规则表、数据问题台账、样本和接口核验。

阶段二｜2–4 周

两个快速试点

客服只读查询 + 管理层日报；包装知识助手可小范围并行建库。

阶段三｜4–8 周

复杂场景离线验证

录入草稿、齐套/约束检查和历史排产回放，再决定是否进入真实计划。

10第二次 AI FDE 会议：直接完成试点决策

第二次会议不再泛谈“AI 能做什么”，而是确认真实流程、核验数据与规则、给候选场景评分，并批准两个两周试点。

0–10 分钟

目标与规则

确认本次只选两个试点。

10–35 分钟

计划流程走查

节点、例外、数据与规则缺口。

35–60 分钟

客服包装走查

查询、录入、包装与异常。

60–80 分钟

系统数据核验

数据口径、权限与接口边界。

80–100 分钟

场景评分

价值、可行性、风险与否决项。

100–120 分钟

PoC 与承诺

样本、指标、人员、周期、决策。

优先分 = 频率 F + 时间/等待 T + 业务影响 V + 数据准备度 D + 规则清晰度 R + 负责人承诺 O − 风险 K

PoC A｜客服订单履约查询助手

  • 订单状态、预计交期、发货或发票中选 3–5 个意图。
  • Agent → 权限校验 → 中间件只读查询 → 结构化回答。
  • 显示数据来源和时间；异常、缺失或冲突时转人工。
  • 验收：响应时间、准确率、询问次数、人工转接与使用率。

PoC B｜管理层生产经营日报助手

  • 覆盖已确认的成品率、出货、异常、物料和人力指标。
  • 数据快照 → 口径校验 → 异常分析 → 日报/PPT。
  • 每个数字可追溯，发送前由柯总确认，不自动下指令。
  • 验收：准备时间、数据争议、发现时效、修改率与采纳率。
一票否决：没有业务负责人、没有真实样本、没有正确答案或无法定义验收指标的场景，不进入 PoC。
