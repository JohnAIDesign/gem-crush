01业务目标与系统边界

系统要让主体人随时知道：本月计划谈谁、谁已谈、谁未谈、谁已排期、谁未排期、哪些会谈取消后待重排、每次谈了什么、有哪些任务需要继续跟踪。

会谈维度未谈 / 已谈
排期维度未排期 / 已排期
变更维度待重排 / 已取消
归档维度待绑定人员 / 待确认 / 已归档
关键设计：四类状态必须分开计算。“已谈/未谈”来自有效会谈记录；“已排期/未排期”来自有效日程。这样临时谈过但未建日程、日程取消但尚未谈等情况都能正确表达。

产品边界

  • 多维表格是业务数据底座，不保存无必要的音视频副本。
  • 飞书日历负责时间安排；妙记负责转写和纪要；飞书任务负责执行；Agent负责对话和编排。
  • Agent不能凭空知道线下临时会谈发生，必须由“开始临时约谈”、录音、上传文件或补录触发。
  • 录音前必须取得当事人知情同意；主体人私密备注不得进入发送给员工的提醒。

02业务流程图与触发责任

每个操作节点均明确“谁触发”。颜色和节点左上角文字标签同时编码，便于产品、业务与开发共同验收。

主体人主动触发发出指令、确认名单、确定时间、启动会谈、确认归档或提出查询。
Agent自动触发理解意图后生成名单、纪要、分析或执行已确认的操作。
系统/其他入口触发由日历时间、妙记结束事件、任务期限、快捷入口或人工补录触发。
触发主体典型触发动作系统约束
主体人主动触发确认名单、确认时间、启动临时会谈、确认纪要、提出查询影响日程、人员、权限或外发任务的动作必须二次确认
Agent自动触发生成候选、整理纪要、执行已确认操作、跨会议分析、形成周月报不得猜测人员、编造纪要或越权发送；回答必须带来源
系统/其他入口触发日历定时、妙记结束、文件上传、任务到期、人工补录、接口回调事件失败需重试和告警；重复事件需幂等去重

03三个关键特殊场景

临时会谈

  1. 点击“开始临时约谈”或对Agent下达指令。
  2. 系统创建“待归档会谈”，记录时间并提示取得录音同意。
  3. 打开妙记/会议录制入口；结束后保存妙记链接。
  4. 若未指定对象，Agent询问“刚才会谈的是谁？”
  5. 确认人员后，关联月度计划、纪要与任务；不得由AI猜测对象。

取消但暂不确定时间

原日程=已取消 → 月度计划保留 → 排期状态=待重排 → 次日提醒 → 创建新日程后自动解除提醒

跨会议记忆查询

当主体人询问“上周我和某某谈的重要事情是什么？”时，Agent先解析人员和时间范围，再检索会谈记录、纪要和任务，返回结论、日期及来源链接；没有证据时不得补写。

技术边界：妙记自动回写、录音一键深链、会议结束事件以及日程双向同步的具体API和企业权限，必须在POC阶段用实际租户验证。不能把产品宣传能力直接视为接口能力。

04多维表格数据模型

01 人员主表

一个人只有一个唯一ID。

  • 姓名、部门、岗位、在职状态
  • 最近约谈日期、年度次数
  • 优先级、敏感等级

02 月度计划表

每人每月一条计划。

  • 月份、人员、名单状态
  • 会谈状态、排期状态
  • 优先级、来源、提醒策略

03 日程映射表

保存业务计划与飞书日程关系。

  • 开始/结束、地点、状态
  • 飞书日程ID、同步结果
  • 取消原因、待重排日期

04 会谈记录表

每次实际会谈一条记录。

  • 人员、时间、地点、性质
  • 妙记链接、总结、重要事项
  • 归档状态、保密等级

05 跟踪任务表

任务必须回溯到来源会谈。

  • 内容、责任人、截止日
  • 状态、飞书任务ID
  • 提醒策略、完成证据

06 提醒与审计表

防重复提醒并记录所有变化。

  • 提醒类型、对象、去重键
  • 发送时间、结果、失败原因
  • 操作者、前值、后值
对象权威来源关联键禁止事项
人员飞书通讯录+人员主表扩展字段employee_id / open_id不得仅用姓名关联，防止重名
月度目标月度计划表plan_id不得因日程取消而删除计划
时间安排飞书日历calendar_event_id不得只改底表不改日程
真实会谈会谈记录表talk_id不得用“日程已结束”代替“已谈”
纪要内容妙记/纪要文档minutes_url/document_id不得向无权人员泄露
执行任务飞书任务+任务映射表task_id/feishu_task_id不得无责任人、无期限直接下发

05系统开发图

数据一致性：飞书日历是时间安排入口，多维表格保存业务关联和同步状态；妙记是会议内容来源，会谈表保存摘要、权限和关联；飞书任务是执行入口，任务表保存来源会谈和汇总信息。

06Agent对话与操作设计

主体人
生成9月份30人的候选名单，优先考虑今年还没谈过的人。
约谈Agent
已生成候选名单草稿。其中18人今年未约谈，12人距上次约谈超过6个月。是否确认加入9月份计划？我不会在您确认前创建日程。
主体人
今天和李明的会谈取消，换个时间吧，暂时不确定。
约谈Agent
请确认：取消今天15:00与研发部李明的日程，保留其本月约谈计划，并标记为“待重排”。我将在明天09:00提醒您重新安排。是否执行？
主体人
上周我跟王芳谈话，有个重要事情是什么来着？
约谈Agent
查到1次会谈：8月24日，第三会议室。重要事项为“质量客诉资料需要在本周形成统一模板”；责任人为王芳，截止8月30日，当前进行中。附纪要和原文位置。

高风险动作必须二次确认

动作确认内容系统结果
移出名单人员、月份、原因名单状态=已移出，保留历史
取消日程人员、原时间、是否待重排取消日程，计划不删除
发送员工提醒接收人、内容、时间过滤私密信息后发送
创建任务任务、责任人、期限、可见范围创建并回写任务ID
绑定纪要人员、日期、纪要链接、保密等级关联并进入可检索状态

07自动提醒规则

编号触发提醒内容完成条件
R01月初名单不足30人缺口人数和候选建议确认名单达到30人或调整目标
R02已确认但未排期未排期清单，建议可用时间创建日程、移出或暂停
R03日程前24小时/2小时对象、时间、地点、上次谈话摘要日程完成或取消
R04取消且新时间未定次日提醒尽快重排新日程创建或计划移出
R05日程结束但无会谈记录询问是否已谈、是否补录已谈/未发生得到确认
R06妙记存在但人员未绑定“刚才会谈的是谁？”绑定人员或标记非约谈
R07纪要待办缺责任人/期限请求补全，不直接下发补全或取消任务
R08任务到期前3天/1天/逾期任务、来源会谈、更新入口完成、取消或延期
R09每周一已谈、未谈、已排期、未排期、待重排周期性摘要
R10月末完成率、纪要完整率、任务闭环率和主题分析月度归档

提醒服务必须具备：去重键 最大频率 暂停 升级 失败重试 发送审计。

08关键开发要求

  1. 幂等：每次操作携带业务ID，重复对话不能重复创建名单、日程或任务。
  2. 双向同步：日历变更必须回写底表；底表变更调用接口更新日历；冲突进入人工处理队列。
  3. 事件驱动：监听日程变更、会议结束、任务状态变化等可用事件；无事件能力时采用定时扫描作为降级方案。
  4. 来源可追溯：Agent回答纪要问题时返回会谈日期、对象和纪要链接。
  5. 权限隔离：主体人私密纪要、员工可见任务和协助人运营权限分开。
  6. 异常处理：接口超时、权限不足、人员重名、日期不完整都必须显式提示，不允许静默失败。
  7. 时间标准：统一Asia/Shanghai时区；修改时保存原值、变更原因和时间戳。
  8. 搜索与分析：按人员、时间、地点、主题、任务责任人和状态构建可检索字段；汇总结果必须引用源会谈。

必须在POC验证的接口

  • 多维表格记录的查询、新增、修改和关联字段。
  • 飞书日程创建、变更、取消、参与人及事件回调。
  • 妙记/智能纪要链接、会议结束后的获取方式与权限范围。
  • 飞书任务创建、责任人、截止日期和状态回写。
  • 机器人私聊/消息卡片、交互按钮和发送结果回执。

09实施路线

POC｜2周先证明闭环建立6张表；30人名单；状态视图；日程创建/取消待重排；手工绑定妙记；提醒验证。
V1｜4-6周打通Agent与飞书核心对话意图、日历/消息同步、纪要关联、任务提取、周报月报和个人历史。
V2｜6-10周增强自动化与治理临时会谈快捷入口、跨会议分析、飞书任务、权限分级、审计、失败重试和运营看板。
首期范围控制：POC不追求自动识别人脸、自动判断员工表现或完全自动发任务。优先确保名单、日程、纪要和任务的关系准确，提醒不遗漏且不重复。

10验收标准

模块必须通过的验收
名单每月30人可增、移出、恢复；重名不误关联；所有变化可追溯。
状态已谈/未谈和已排期/未排期独立准确；临时会谈和取消待重排状态正确。
日程创建、变更、取消与飞书日历一致；重复指令不重复创建。
临时会谈可快速创建待归档记录；未绑定人员会触发询问；不可自动猜人。
纪要每次会谈可关联妙记、总结、重要事项和任务；有保密等级。
查询能查询个人全历史、指定时间范围和跨会议汇总，且给出来源链接。
提醒未排期、取消待重排、会后未归档、任务到期均可触发，并能去重和停止。
权限普通员工不能查询主体人私密纪要；发送员工的提醒不包含私密备注。
审计每次Agent和人工变更均记录操作者、时间、前后值和执行结果。
