01执行摘要

本次会议不是一次通用AI工具介绍会，而是苏州海顺光电把AI从“个人试用”推进到“业务落地”的实施部署会。会议形成五项核心共识：

  1. 业务流程先于模型。 业务部门必须说清任务、流程、规则、数据和验收标准，AI团队才能把业务逻辑转化为可执行的Agent、MCP工具与Skill。
  2. 从八类原子动作寻找切入点。 将日常任务拆解为获取、搬运、整理、核对、判断、生成、沟通和执行，再识别其中“高频、高耗时、高复杂度、数据可得”的AI机会。
  3. 首期只做一个高优POC。 不同时启动全公司AI，也不直接挑战全自动排产。建议首期选择“产品应用场景与目标客户发现助手”，两周内用真实产品和客户样本验证价值。
  4. 生产计划先完成四流梳理。 排产智能化的前提是把业务流、信息流、工作流、决策流从“鱼头到鱼尾”画清楚，并补齐历史数据、规则与例外。
  5. 最终目标是能力转移。 FDE团队不是长期替业务部门代做，而是通过模板、Skill、SOP和培训，让业务人员逐步具备自主使用AI解决问题的能力。
首要决策建议： 批准“产品应用场景与目标客户发现助手”作为首期POC；研发部提供可复用的Agent/MCP/Skill能力，销售部提供产品、客户与评判标准，FDE团队负责集成、测试和验收。生产计划部并行完成流程与数据准备，不进入全自动排产开发。

02会议目标与形成的判断

会议目标

  • 识别研发、销售和生产计划部可由AI改善的具体工作场景。
  • 明确业务方、AI FDE团队和IT之间的责任边界。
  • 确定首期POC及其输入、输出、数据、指标和时间安排。
  • 建立从通用工具试用到企业级知识与智能系统的演进路径。

会议形成的实施判断

判断具体含义对实施的影响
AI不是“无米之炊”输入不完整、历史数据不足、业务规则模糊时，模型无法稳定输出每个场景必须先提交需求卡、样本和正确答案
Agent是业务连接器Agent负责理解任务、调用工具、组织结果，不替代业务责任业务人员仍是需求定义者和最终评判者
MCP/API是受控工具通道外部数据库和内部系统应通过授权接口调用明确字段、权限、频率、失败处理和审计
Skill优于一次性提示词将检索步骤、分析逻辑、输出格式和质量检查固化成果可复用、可测试、可持续优化
POC优于全面铺开先证明一个业务结果，再复制到相似场景管理层以里程碑看效果，不以安装人数看效果
HTML适合共享结果交互式报告便于阅读、检索和跨端分享HTML用于展示；ERP、Excel和原始文件仍作为权威数据载体

03三部门业务场景与实施建议

研发部：把“会用工具”升级为“可复用能力”

当前进展

  • 已尝试将复杂任务拆解为八类原子动作。
  • 已探索通过Agent与MCP接口连接启信慧眼等外部数据平台。
  • 已在企微群分享案例资料，具备一定的内部示范基础。

推荐建设方向

  1. 建立统一的外部企业情报检索Skill：固定查询条件、字段映射、证据引用、去重、可信度和输出模板。
  2. 建立产品—技术—行业应用知识结构：把产品参数、关键能力、适配条件、限制条件和案例形成结构化信息。
  3. 对查询结果执行证据约束：企业信息、竞争动态和市场判断必须显示来源、更新时间与置信度；无证据内容不得作为事实输出。
  4. 将研发侧的工具能力服务化，为销售POC提供可调用的企业检索、分类和报告生成模块。

首期交付

  • 1个企业信息检索Skill。
  • 1份字段字典与输出Schema。
  • 10个已人工核验的正确样本。
  • 失败、无结果、同名企业和接口异常的处理规则。

销售部：从产品信息生成应用场景并发现目标客户

业务需求

  • 输入产品功能、材料特性或技术参数，生成可解释的应用场景。
  • 匹配当前可能使用该产品的目标企业。
  • 发现未来在扩产、替代材料、工艺升级或新产品中可能产生需求的潜在企业。
  • 跟踪竞争企业、替代方案与市场变化，用于销售判断。

推荐的AI动作链

产品资料获取（AC1） → 参数与能力整理（AC3） → 应用条件核对（AC4） → 场景推断（AC5） → 企业搜索（AC1） → 匹配评分（AC5） → 线索报告生成（AC6）

输出必须包含

输出模块必须内容
产品能力摘要关键参数、解决的问题、适用边界、不能做什么
应用场景场景描述、所处行业、使用环节、触发需求的条件
目标客户企业全称、地区、行业、匹配理由、证据来源、更新时间
未来潜客需求触发信号、推断依据、置信等级，不得将推断表述为事实
竞争情报经确认的竞争企业全称、产品/客户/扩产动态及来源
销售建议建议联系部门、验证问题、下一步动作，由销售人员人工确认
会议中出现的“斯蒂克、黄老板、赛武”等名称需由业务方确认企业全称、关联主体和关注对象。“黄老板”等非标准实体不得直接作为数据库查询条件或正式报告对象。

生产计划部：先把四条流画清楚，再谈智能排产

“鱼头到鱼尾”的建议范围

需求/订单进入 → 交期确认 → 库存与到料核对 → BOM/工艺核对 → 产能与设备核对 → 排产初稿 → 跨部门确认 → 计划下达 → 执行反馈 → 异常重排 → 完工关闭与复盘

必须同时梳理的四条流

流程要回答的问题必备交付物
业务流从收到需求到完工关闭，业务如何流转？端到端泳道图
信息流每一步需要什么信息、来自哪里、何时更新？数据流图、字段清单、系统清单
工作流谁操作、谁审批、谁协同、在哪个系统完成？角色责任矩阵、交接与回退规则
决策流如何决定优先级、齐套、换线、插单、延期与重排？决策表、规则表、例外清单

生产计划部需要补充的数据

  • 最近8–12周的订单、预测、排产、工单、实际完工与交期变更记录。
  • BOM版本、工艺路线、设备能力、班次日历、换线/清线时间、良率和损耗。
  • 可用、锁定、待检、不合格和在途库存的统一定义与历史快照。
  • 插单、缺料、停机、质量异常、返工等至少20个完整案例。
  • 计划员实际使用的判断规则，以及“系统规则之外”的人工经验。

阶段边界

首期不建议开发“全自动排产”。可先验证：订单齐套检查、跨部门信息自动收集、约束冲突提示或生产异常日报。AI只生成建议，不自动下达生产计划。

05建议的首期POC

POC名称

产品应用场景与目标客户发现助手（Sales Intelligence Agent）

为什么优先选择该场景

  • 业务价值直接： 输出可用于销售线索拓展与行业研究。
  • 现有能力可复用： 研发部已有Agent、MCP和外部企业数据平台的实践。
  • 数据边界相对清晰： 首期以产品资料、公开/授权企业信息和人工标签为主，不依赖复杂ERP改造。
  • 验证周期短： 可在两周内通过3–5个产品和已知客户样本进行离线测试。
  • 容易复制： Skill、字段和评判方法可复用至竞品跟踪、供应商发现和研发情报。

POC范围

输入： 1个产品族、产品说明书/参数、已知应用、目标区域、已知客户与非目标客户样本。
处理： 产品能力抽取、应用场景生成、企业检索、实体去重、匹配评分、证据校验。
输出： 20–50家候选企业清单、匹配理由、证据链接/来源、置信等级、建议验证问题。
不包含： 自动联系客户、自动写入CRM、将模型推断作为事实、未经授权抓取或传播受限数据。

两周实施节奏

时间工作交付
T+1–2天锁定产品、用户、范围和正确样本POC需求卡、产品资料包、验收表
T+3–5天固化应用场景逻辑与企业检索SkillSkill v0.1、字段Schema、测试集
T+6–8天接入授权数据工具并生成第一批结果候选企业清单v0.1、证据与错误清单
T+9–10天销售与研发联合评审逐条评分、漏报/误报/实体问题

T+13–14天现场演示与验收POC报告、ROI估算、推广/停止决定

建议验收指标

  • 证据覆盖率：目标企业关键判断均有可追溯来源，目标100%。
  • Top 20有效率：销售确认“值得进一步验证”的企业占比，建议目标不低于70%。
  • 实体准确率：企业全称、统一主体和地区匹配准确，建议目标不低于95%。
  • 人工时间：形成一份同等质量清单的人工耗时下降60%以上。
  • 可解释性：每个候选企业均能回答“为什么匹配、依据是什么、下一步问什么”。
  • 风险控制：无来源推断不得写成事实；敏感数据不得进入未获批准的外部模型。

继续或停止条件

继续： 核心指标达标、业务愿意持续使用、数据成本可控、下一阶段收益明确。
调整： 有价值但命中率不足，能够通过补充样本、规则或数据源改善。
停止： 无法取得可靠数据、业务无法提供正确答案、使用频率低或合规风险不可接受。

06推荐技术与知识架构

业务入口 → Agent任务编排 → Skill/规则 → MCP/API工具层 → 授权数据源与知识库 → 证据化结果 → 人工确认与反馈 → 日志与持续优化

分层要求

  1. 业务入口层： 企业微信、内部页面或固定HTML报告，入口要贴近日常工作。
  2. Agent层： 识别意图、拆解任务、选择工具、检查必填参数和输出格式。
  3. Skill层： 固化检索、判断、引用、评分和质量检查；必须版本化并有负责人。
  4. 工具层： MCP用于授权查询，API用于受控系统交互；接口失败时必须明确提示，不得编造结果。
  5. 数据与知识层： 内部权威资料、历史样本、ERP/中间件数据和获授权外部数据；必须标注来源、版本、更新时间和权限。
  6. 治理层： 最小权限、日志、脱敏、人工确认、错误反馈、版本回退和成本监控。

07知识库与工具使用建议

初期工具

可使用会议中提到的Work8.0（产品名称与版本需进一步确认）、豆包等通用工具进行非敏感资料的分类、摘要和原型验证；涉及客户、配方、工艺、价格、合同、研发和生产数据前，必须完成企业合规、数据存储位置、账号权限和模型训练使用条款确认。

知识库最小规范

每条知识至少包含：标题、业务类别、正文、来源、责任人、适用范围、版本、生效日期、失效日期、保密级别和最后复核时间。没有来源或已过期的知识不得作为确定答案。

私有化部署时机

不建议一开始就把“私有化部署”当作成果。应先通过POC确认真实使用频率、知识范围、检索质量和权限模型，再决定内网部署、专业知识库或定制模型方案。

HTML与Office文件的边界

HTML适合发布结构化报告、交互目录、跨端阅读和展示结果；Excel适合数据交换与核验，ERP/PLM/MES仍应是业务主数据和交易记录的权威来源。HTML不能取代需要审计、审批或持续写入的业务系统。

10下一次会议建议议程

  1. 10分钟： 确认POC目标、产品范围和验收指标。
  2. 20分钟： 销售部讲解产品、客户样本与“好线索”标准。
  3. 20分钟： 研发部演示MCP检索能力、数据字段和异常处理。
  4. 25分钟： FDE团队演示第一批候选企业、证据和评分。
  5. 20分钟： 逐条核验误报、漏报、实体错误和无证据推断。
  6. 15分钟： 生产计划部汇报四流图和数据缺口，不讨论全自动排产方案。
  7. 10分钟： 明确下一版本、责任人和是否进入推广阶段。
会议门槛： 没有业务负责人、没有真实样本、没有正确答案、没有可量化验收指标的场景，不进入POC开发。

11风险与控制要求

  • 数据风险： 客户、工艺、合同、价格和研发资料进入外部模型前必须审批并脱敏。
  • 事实风险： 企业、竞争和市场结论必须有来源；预测内容须标识为推断。
  • 系统风险： 查询与写入分离，首期仅做只读查询和报告草稿。
  • 组织风险： 不以培训人数、软件安装量或文档数量衡量AI成效。
  • 使用风险： AI建议必须由对应岗位人员审核，不自动触发销售承诺、生产计划或质量放行。
  • 版权与许可： 外部数据库、网页和文档的使用应符合授权范围及许可条款。

12结论

苏州海顺光电已经具备从AI工具试用进入FDE业务实施的基础：研发部有Agent与MCP探索，销售部有明确的客户发现需求，生产计划部也识别了跨部门数据收集与排产决策的核心矛盾。下一步的关键不是扩大工具安装，而是通过一个边界明确、数据可得、可量化验收的POC建立可信结果。

建议以“产品应用场景与目标客户发现助手”为第一突破口，两周形成可验收成果；同时由生产计划部完成四流梳理和历史数据准备。POC成功后，再将已验证的Agent、MCP、Skill、知识结构和治理机制复制到研发情报、生产计划、知识库与更多部门，逐步实现“授人以渔”。
