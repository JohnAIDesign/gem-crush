两条产品线的工艺路线

PTP 路由 A 印刷→涂布→涂布后检品→分切 PTP = 药用泡罩铝箔
PTP 路由 B 涂布→印刷→印刷后处理→印后检品→分切 特殊情况:涂布后直接复合。涂布在前是排产的关键耦合点(见约束 C5)。
SP 主路由 印刷→印刷后处理→印刷后检品→复合1→复合2→复后检品→分切 SP = 药用复合膜/袋。特殊情况:复合后涂布,涂完再复合。

03补充数据清单 —— 智能排产的燃料

主数据六类(静态:建一次,持续维护)

D1机台主数据档案 · 设备能力矩阵最优先 · 治痛点7
  • 基础:机台编号、名称、工序(印刷/涂布/复合/分切/检品)、所属车间(新/老)、班制
  • 能力:色数上限;分品种实测机速(按 PTP/SP × 材质 × 克重);有效幅宽上下限(C9/C12);承印厚度;上胶量区间(C3);支持底涂(C4 排除 1024)与胶水类型(C11 排除 PA);特殊能力标志(压易撕仅 SP6色 C7、圆刀/平刀、塑料管 C12)
  • 运行:稼动率/OEE、计划保养日历、机速修正表(C2 联邦机按 80)
D2换型时间矩阵合单排序的量化基础
  • 维度:色数差 × 幅宽差(套裁降宽)× 颜色深浅转换 × 油墨清洗 × 胶水/底涂切换 × 圆刀换刀 × GMP 清场
  • 结构:from 工艺状态 → to 工艺状态 = 分钟数。没有这张表,"从宽到窄"只是经验,不是可计算的排序代价
D3物料主数据 + BOM + 备库料台账治痛点6/8
  • 物料:编码、材质(PTP 铝箔/PE/PET/PA/ACL/片材…)、厚度、宽度、供应商、采购周期
  • 规格标准化字典:统一书写顺序(建议"厚度×宽度"单向)、全角/半角括号统一、自动解析函数把历史订单洗成标准件
  • BOM:产品 → 原膜 + 胶水型号 + 油墨 + 底涂(1024/168/172)+ 管芯 + 包装
  • 备库料/余料台账:编号、材质、宽度、长度/重量、库位、可用状态——支撑"备库料分切订单"自动匹配
D4结构化工艺数据库治痛点7
  • 每产品工艺单字段化:工艺路由(PTP-A / PTP-B / SP-1 / 特殊)、色数、颜色组(含金色标志)、满版标志、上胶量、胶水型号、底涂类型、印后处理(压易撕/上光油)、分切刀型、成品宽幅组合
  • 机台 × 产品 机速实测表(D1 的数据来源)
D5客户主数据
  • 客户等级(ABC/战略)、主供产品、历史月均量与波动系数
  • 交期严格度(延期罚则)、允许分批交货、允许代料清单(药包材代料需客户注册/变更批准,见 §05)
D6良率与质量档案治痛点4 · 支撑投入量倒算
  • 各工序标准良率(印刷/涂布/复合/分切/检品剔除率)
  • 投入量倒算:首工序投入 = 交付需求 ÷ Π(各工序良率)——没有良率数据,合单批量算不准,分切尾数永远缺
良率倒算是合单的隐藏前提:客户要 100 万件,若印刷-涂布-分切累计良率 95%,首工序必须投 105.3 万件。良率档案缺失 = 合单批量系统性偏小。

04智能排产逻辑组合 —— 推断性方案 · 待验证

目标函数

主目标:交期达成率最大化(按客户等级加权);次目标:总换型时间最小化、机台负载均衡、在制品滞留最短。一票否决硬指标:时间窗违约次数 = 0(C5/C6)、硬约束违规 = 0(C1–C4、C7–C12)。

约束体系:硬约束做过滤器,软约束做排序代价

约束类别编码方式

排产流水线八步(引擎主流程)

S1
订单接入与标准化
依赖 D3
订单池 → 规格解析清洗(厚度/宽度乱序、括号全半角)→ 标准化订单。痛点 8 在此终结。
S2
BOM 展开与齐套检查
依赖 D3 + T2
订单 → BOM 展开 → 现存+预留+在途比对 → 输出齐套日与缺口单清单。痛点 2/3 在此拦截,PE 到齐日(C8)在此产生。
S3
合单聚类
依赖 D2 + D3
可排订单按"材质 × 规格 × 色组 × 胶水"分组,组内从宽到窄套裁,输出合单建议与经济批量阈值。
S4
优先级评分卡
依赖 T1 + D5
优先级分 = w1×交期紧迫度 + w2×客户权重 + w3×订单金额 + w4×延期罚则 − 样品/小单折扣;权重与排产员共同标定。
S5
工艺路线展开
依赖 D4
合单批次 → PTP-A / PTP-B / SP-1 / 特殊路由 → 工序 DAG(含检品节点与时间窗标记)。
S6
机台分配
依赖 D1
工序任务 → 能力矩阵硬过滤得候选机台集 → 按负载与换型代价择优。C1–C4、C7、C9–C12 全部在此生效。
S7
有限产能时序编排
依赖 D2 + T3/T4
正排+倒排结合,插入 min/max 时间窗(C5/C6)与换型时长,输出机台甘特图。联邦机按机速 80 折算(C2)。
S8
冲突检测 · 人机协同 · 回写
依赖全部
甘特 → 十三条规则校验器 → 违规红色预警 → 排产员确认 → API 回写 ERP。痛点 5 的双录在此消除。
S8 保留人工确认关:智能排产建议化而非黑箱化,排产员从"编排者"升级为"审核者"——没有 MES 的工厂,这是最稳的落地姿态。

急单与插单机制(治痛点 1 的根源)

滚动排产:日粒度冻结区(今天+明天不动)+ 3 日滚动重排 + 2 周展望。插单模拟(what-if):新急单进入 → 只重排冻结区外 → 输出代价清单(哪些单延后多久、哪些换型被破坏)→ 排产员带着代价去和业务谈。CTP 接单校验:客服下单时引擎用剩余产能模拟出可承诺交期,从源头减少"接单即注定延期"的急单。

05药包材行业特有考量(GMP)

  • 清场与防交叉污染——批间换型必须含清场时间,药监检查关注点。换型时间矩阵(D2)里的清场不是可选项。
  • 代料的法规面——药包材变更通常需客户注册/变更备案批准,"生产线能代" ≠ "合规能代"。代料矩阵必须带客户批准状态字段,这才是痛点 2 的完整解。
  • 印刷文字质量风险——C1"2色机不做小文字"的本质是版辊精度/套印误差导致药品标识不清 = 整批报废 + 客户审计风险,应升级为质量硬门而非"尽量"。
  • 批号追溯链——排产批次 → 生产批 → 检品批 → 留样;批次号应贯穿排产表与 ERP 工单(也治双录痛点 5 的字段对齐)。
  • 洁净区资源——若印刷/复合在 D 级洁净区,洁净区工时与更衣/清场也是产能约束。
  • YBB 检测周期——出厂检验耗时计入交期承诺,CTP 报交期时不可只算生产。

换型时间占比 / 设备 OEE换型占比下降,OEE 上升(D2 + 聚簇优化)
24h 时间窗违约次数恒为 0(C5/C6,校验器一票否决)
库存准确率 / 规格标准化覆盖率分别趋 100%(阶段 0 出口)
双录工时归零(ERP 回写上线)

08待验证:海顺现场核验十问

  1. 机台完整清单:印刷 / 涂布 / 复合 / 分切 / 检品各几台?新旧车间分布?
  2. 每台机速现状:哪些有数、哪些缺?(D1 的 P0 工作量)
  3. 班制:几班几倒?年有效工时?
  4. ERP 型号(金蝶/用友/定制?)及有无开放接口或中间表?(S8 回写可行性)
  5. 日均订单量与在制批次规模?(算法规模与选型依据)
  6. "联邦"是机台名还是设备品牌?涂布后印刷的单子占比多少?(C2 影响面)
  7. 样品单 / 小单占比?(评分卡权重标定)
  8. 是否有 MES / 报工终端 / 扫码?(T3/T4/T5 的采集方式)
  9. 代料现在的审批流程?客户注册变更怎么做?(D5 + §05)
  10. 检品是抽检还是全检?(检品工序产能计算)

09FDE 现场梳理 Playbook —— 访谈 · 采集 · 验证 · 2026-08-27 追加

总原则:不是做需求调研,是做"约束库 v0.1 的参数化与扩编"。《排产逻辑步骤及注意点.xlsx》已经是第一份访谈记录——C1–C13 是约束库初版,PTP/SP 路由是流程骨架。现场只干三件事:①给每条约束补上缺的数字;②验证每条现在还准不准;③挖出师傅知道但没写下来的第 14、15 条。

四个手法(比问什么更重要)

表 9-1 · 跟单走 / 三角化 / 出题考试 / 采集即建模

跟单走挑一张在产的真实工单,从客服下单跟到入库发货,每个节点停一下:谁接手、看什么单据、做什么判断流程图的真相在路上,不在会议室
三角化规则问人、数字拿记录、矛盾现场看——口述机速 vs 机台记录 vs 现场掐表人记不准数字,记录不会说话,观测裁决冲突

采集即建模每一项收集物对应未来系统的一个字段(D1–D6 / T1–T8)不收用不上的,不设计填不出的

七条流程线(要摸清的骨架)

  1. 订单旅程——下单 → 订单统计表 → 排产 → ERP 双录 → 工单流转 → 各工序 → 入库发货
  2. 排产员的一天——几点排、改几次、急单怎么插
  3. 换型的完整动作——停机 → 清场 → 换版换刀 → 首件确认 → 开机达标;哪一段算"换型时间"要现场定义清楚
  4. 物料链——BOM 在哪、备库料怎么记、代料怎么走
  5. 异常流——机台坏了 / 料不来 / 客户改单,现在怎么重排
  6. 交接班与日报——数据怎么产生、良不良怎么混进去的(痛点 4 现场取证)
  7. 检品规则与放行——抽检/全检、判定标准、放行权限

人心与节奏

人心:排产员和老师傅是盟友不是被告。话术永远是"我来把师傅的经验变成系统,让机器先学会你的排法",不是"我来查你们的数据为什么不准"——厂内自主推改革,最大阻力从来不是技术,是"这东西是不是来替代我的"。
